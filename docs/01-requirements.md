# 01 需求与成功标准

## 用户与业务问题

运营人员需要在主题确定但预算、截止时间有限的情况下，得到一份有素材依据、步骤明确、可核对费用的活动内容方案。工具可能失败或只返回部分资料，原计划也可能超出预算；系统应让模型依据实际工具结果改选方案，并保留已有成果。

输入为 `id`（可选）、`theme`、`budget`、`deadline`。预算是最多两位小数的非负模拟单位；截止时间必须是带时区的 ISO 8601 时间。缺预算/截止时间返回 `needs_input`，不猜测默认值，也不调用模型。`id` 未提供时由输入哈希生成；续跑建议明确提供稳定 `id`。

## 范围

交付 CLI、真实模型工具调用适配器、四类业务工具、停止动作、本地状态文件、Trace、测试和在线/离线证据。素材和工具由本地函数模拟；脚本用模板生成。Agent 决策由在线语言模型完成，Mock 单独标记。

完成的含义是“保存一份满足约束的方案”，不是制作/发布活动。方案包含分镜或卡片脚本、素材引用、依赖步骤、制作工时、费用与人工核实事项。

## 验收矩阵

|要求|判定条件|证据入口|
|---|---|---|
|正常完成|存在计划文件，费用和截止时间均满足|`examples/live/normal/`|
|缺预算|needs_input，零工具/模型调用|`examples/live/missing-budget/`|
|缺截止时间|needs_input，零工具/模型调用|`examples/live/missing-deadline/`|
|工具失败|失败步骤标 failed，成功素材保留，模型调整动作|`examples/live/tool-failure/`、`tool-failure-persistent/`|
|预算超限|12实际报价超预算10，改8，重估并保存|`examples/live/over-budget/`|
|无可行预算|预算4，最低规格5，未保存，报告缺口|`examples/live/no-feasible/`|
|重复执行|相同任务重放，新增调用0，方案内容不变|`examples/live/repeat/`|
|失败续跑|先保存失败，再从保留脚本保存成功|`examples/live/resume/`、`resumed/`|
|部分成功|保留有效图片，改用lite|`examples/live/partial/`|
|无资料|没有相关素材，不虚构生成结果|`examples/live/no-materials/`|
|截止不足|不保存违反时间约束的方案|`examples/live/deadline/`|
|执行上限|返回未完成与原因，结果可续跑|`tests/agent.test.mjs`|

## 核心不变量

1. 只有成功检索的素材才能生成脚本；视频规格必须有视频素材。
2. 只有成功脚本才能估算；只有已估算且保存时仍满足约束的脚本才能保存。
3. 失败尝试保留在日志中，不写入成功缓存或伪造脚本。
4. completed 必须对应已落盘方案；重放时核对文件与检查点内容。
5. 成功生成多个备选脚本，不代表多个备选内容已经制作或收费。
6. 修改已给定的需求必须新建任务；补齐原先缺失字段可以保留原id。

## 非目标

不追求生产级多租户、分布式锁、真实发布、视频渲染或最优营销效果；不把模拟单位当人民币，不把一次在线验收当模型准确率。无需界面、部署或多Agent。
