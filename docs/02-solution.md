# 02 方案与技术取舍

## 模型和执行器的边界

`src/model.mjs` 使用 Chat Completions 原生工具调用协议。每轮把需求、持久状态、最近30条观察、当前时钟和剩余动作预算交给模型；模型必须返回一个原生 `tool_call`。执行器验证工具名、参数、依赖后调用本地工具，并将实际返回写入检查点。下一轮模型再读取最新观察。没有预先生成决策日志，也不由条件分支选择替代规格。

采用“每轮状态快照”而非依赖服务商隐藏会话的方式，便于换模型、重启和审阅。模型每轮仍通过 API 原生 function calling 选择动作；工具结果在下一轮快照中提供，不伪造 assistant/tool 消息。

工具：`search_materials`、`generate_script`、`estimate_cost`、`save_plan`；`finish` 为结束动作。每个动作有一句 `rationale`，只保留可审阅的决策依据，不要求模型内部思维链。

参考接口：[OpenAI 官方 Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。当前验收服务商为 DeepSeek，使用其兼容的 `/chat/completions` 接口；其他兼容服务商需自行验证工具调用能力，不声称已测。

## 动态路径

|观察|在线模型实际动作的可能选择|执行器负责|
|---|---|---|
|premium报价12、预算10|生成standard，再估算8并保存|拒绝预算不满足的保存|
|脚本一次失败|复用成功素材重试|失败不缓存、不生成成功记录|
|premium持续失败|改standard/lite或停止|保留所有失败与成功结果|
|primary只有图片|生成lite；也可能检索备用图片|视频依赖硬校验|
|预算4且最低5|停止并报告缺口|最终摘要只列实际估算证据|
|保存失败后重启|直接重试保存/重新估算|从状态恢复，不强制重做成功步骤|

模型的动作会变化，不能把例子理解成固定唯一轨迹。验收时为了稳定展示12→8，向模型提供“素材支持时先试premium”的演示偏好；该偏好是输入，写入汇总，代码未强制执行premium或standard路径。即使偏好不合理，工具守卫也不能被绕过。

## 状态、幂等与恢复

`Store` 在 `root/id/` 下保存 `state.json`、`plan.json`，并使用 `wx` 文件锁限制同id并发。状态包含不可变需求指纹、成功素材/脚本/估算、缓存、故障消费计数、事件、会话号、用量和模拟工时。每步后通过临时文件+rename替换检查点。

- `search_materials`、`generate_script` 成功结果缓存；键不含rationale，只含语义参数。
- 估算随时间变化，不缓存旧执行结果；保存前再次重算。
- 故障只缓存消费次数，不缓存失败输出为成功结果。
- completed任务校验已保存文件内容后重放；方案缺失/篡改报错，不能直接成功。
- 保存文件先完成原子替换，随后提交状态。若两者之间崩溃，续跑可从同请求方案恢复状态。
- 缺字段的状态未产生工具副作用，允许补齐；其余改需求必须新id。

文件锁是本机单文件保护，不是分布式事务；崩溃残留 `.lock` 需确认进程结束后手动移除。只保证本地合成工具和正常磁盘条件下的幂等/恢复，不承诺真实外部付费服务 exactly-once。

## 费用与时间

目录在 `data/catalog.json`：premium 12/180分钟、standard 8/90分钟、lite 5/40分钟。每种规格都有费用分项和素材类型要求。工具费用当前均为0；检索2分钟、脚本5分钟、估算1分钟、保存1分钟，均为合成工时。失败和实际执行均消耗工具工时；缓存不重复消耗。

```text
总费用 = 选中方案费用分项之和 + 已发生工具费 + 保存待发生费
有效当前时刻 = max(系统当前时间, 任务逻辑起点 + 累计模拟工具工时)
预计完成 = 有效当前时刻 + 剩余制作工时 + 待发生保存工时
可行 = 总费用 <= 预算 且 预计完成 <= 截止时间
```

保存动作已计入工时后，不再把保存耗时重复相加。保守串行制作任务工时总和与规格一致。预算缺口与时间缺口分别计算；真实模型 API 费用只记录tokens，不换算模拟预算，不编造服务商账单。

## 结果可信度

工具schema和依赖由服务端校验，不信任模型提供的费用、文件路径或“完成”文字。`finish completed` 没有保存证据会失败。最终原因由成功结果生成；模型原始reason保存在 `model_note`，标记 `model_note_is_unverified`。这样能保留审计信息而不让模型总结覆盖事实。

## 为什么不用框架

本题需要一个决策循环和少量状态化工具。原生实现便于逐行解释守卫、失败缓存与持久化语义，也避免框架安装。没有使用LangGraph/ADK等框架，所以不存在框架版本或框架能力归属的混淆。环境、安装、运行不依赖IDE或全局npm。
