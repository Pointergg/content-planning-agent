# 05 实现复盘与下一步

本节记录此次辅助实现中观察到的问题和解决方式，不冒充候选人独立工作的经历或口述。

## 最难的问题：计划文字与执行事实一致

模型能够给出听起来合理的总结，但可能把目录参考价说成实际工具估算，或者把保存方案说成完成内容生产。仅靠提示词不足以保证交付可信。

解决方式是把工具状态、费用和文件保存视为权威证据：估算不通过不能保存，没有保存不能宣称完成，最终摘要从成功工具结果生成。模型原话保留但标为未验证。任务计划中的制作、审核、发布仍标记planned。

## 工程上的学习与改进

- 预算问题不是把12改成8的字符串替换，而是生成另一个规格、重新估算，并保留原成功脚本和素材。
- 不把固定重试写成Agent能力：一次失败后是否重试、持续失败后是否换规格由真实模型选择，执行器只约束安全与真实性。
- 保存失败并不意味着全部重做。先持久化成功依赖和故障消费次数，再允许同id续跑。
- 重放检查点不等于文件一定存在；需要核对已保存方案。文件与状态之间的崩溃窗口需要单独恢复路径。
- 时间约束需考虑时区、有效日期、累计工时与保存前的时间变化。二进制浮点也会影响两位小数预算验证。
